# The database schema, in git

The live schema lives in Supabase. Until now it existed *only* there — which meant the
repository could not rebuild the system it describes. These files close that gap.

`tables.sql` is a structural snapshot (tables and column types), regenerated by the query
at the bottom of this file. It is documentation and disaster-recovery reference, not a
migration runner: constraints, indexes, RLS policies, functions and cron schedules are
recorded in `objects.md` alongside the reasoning that motivated each.

**Why not a migration tool.** This is a single-operator research system whose schema
changes a few times a month, always deliberately, always with an ADR or finding behind
it. A migration framework would add a moving part without removing a risk. What matters
is that the schema is *readable in git* and that every object's purpose is written down —
so a future session (or a rebuild from scratch) can reconstruct intent, not just columns.

Regenerate `tables.sql` with:

```sql
select string_agg(def, E'\n') from (
  select 'create table tennis.' || c.relname || ' (' || E'\n  ' ||
    string_agg(a.attname || ' ' || format_type(a.atttypid, a.atttypmod) ||
      case when a.attnotnull then ' not null' else '' end, E',\n  '
      order by a.attnum) || E'\n);' as def
  from pg_class c
  join pg_namespace n on n.oid = c.relnamespace
  join pg_attribute a on a.attrelid = c.oid and a.attnum > 0 and not a.attisdropped
  where n.nspname = 'tennis' and c.relkind = 'r'
  group by c.relname order by c.relname
) t;
```
